  <name>Task 2: Create config.py with two-file config loading (.env + config.yaml)</name>
  <files>bot/config.py, config.yaml</files>
  <action>
Create the configuration system that loads secrets from `.env` and non-secret settings from `config.yaml`.

1. Create `bot/config.py`:

   **EnvSettings class** (pydantic-settings BaseSettings):
   - `bot_token: str` — required
   - `bot_username: str` — default "koreanstory_bot"
   - `keycrm_api_key: str` — required
   - `shopify_api_token: str | None = None` — optional, bot works without Shopify
   - `shopify_store_url: str | None = None` — optional
   - `admin_user_ids: str = ""` — comma-separated string "129462784,183618567"
   - Property `admin_ids -> list[int]`: splits admin_user_ids by comma, strips whitespace, converts to int list
   - Config: `env_file = ".env"`, `env_file_encoding = "utf-8"`

   **AppConfig dataclass** (combined config):
   - `env: EnvSettings`
   - `brand_name: str`
   - `website_url: str`
   - `support_chat_id: int`
   - `about_text: str` (info page content, can be empty for now)
   - `contacts_text: str`
   - `payment_text: str`
   - `delivery_text: str`

   **load_config() function:**
   - Instantiate `EnvSettings()` (auto-loads .env via pydantic-settings)
   - Open and parse `config.yaml` with `yaml.safe_load()`
   - Construct and return `AppConfig` with values from both sources
   - Use `yaml_data.get("key", "")` for optional text fields

   Import: `from pydantic_settings import BaseSettings` (note: underscore, not hyphen)

2. Create `config.yaml`:

Do NOT use `from pydantic import BaseSettings` — that was pydantic v1 and will fail on pydantic v2. Use `from pydantic_settings import BaseSettings`.
