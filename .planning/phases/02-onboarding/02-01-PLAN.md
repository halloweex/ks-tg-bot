<task type="auto">
  <name>Task 2: Implement onboarding handler and modify /start for returning users</name>
  <files>bot/handlers/onboarding.py, bot/handlers/common.py</files>
  <action>
1. Create `bot/handlers/onboarding.py` — the phone input handler:

   - Import: `asyncio`, `re`, `Router`, `FSMContext`, `Message` from aiogram; `texts` from bot; `save_user` from bot.db; `KeyCRMClient` from bot.services.keycrm; `ShopifyClient` from bot.services.shopify; `OnboardingStates` from bot.states
   - Create `router = Router()`
   - Define `PHONE_PATTERN = re.compile(r"^\+380\d{9}$")`
   - Create handler `process_phone(message, state, keycrm, shopify)` filtered on `OnboardingStates.waiting_phone`:
     a. Normalize input: `raw = message.text or ""` then `phone = re.sub(r"[\s\-\(\)]", "", raw.strip())` — strips spaces, dashes, parentheses before validation (Pitfall 3 from research)
     b. Validate: if `not PHONE_PATTERN.match(phone)` → `await message.answer(texts.ERR_INVALID_PHONE)` and return (stays in waiting_phone)
     c. Acknowledge: `await message.answer(texts.MSG_PHONE_ACCEPTED)`
     d. Build parallel tasks: `tasks = [keycrm.get_orders_by_phone(phone)]` + conditionally append `shopify.get_orders_by_phone(phone)` if shopify is not None
     e. Run: `results = await asyncio.gather(*tasks, return_exceptions=True)`
     f. Analyze results — distinguish "API returned empty list" from "API raised exception" (Pitfall 4 from research):
        - Iterate results. If `isinstance(r, list)` → all_failed = False; if `len(r) > 0` → has_orders = True
        - If all_failed (every result is an exception) → `await message.answer(texts.ERR_API_UNAVAILABLE)` and return (stays in waiting_phone for retry)
        - If not has_orders (APIs worked but returned no orders) → `await message.answer(texts.ERR_PHONE_NOT_FOUND)` and return (stays in waiting_phone for retry)
     g. Success: `await save_user(message.chat.id, phone)` → `await state.clear()` → `await message.answer(texts.MSG_PHONE_VERIFIED)`
   - Type hints: `keycrm: KeyCRMClient`, `shopify: ShopifyClient | None` — these come from dp workflow_data via aiogram DI

2. Modify `bot/handlers/common.py`:
   - Add imports: `from aiogram.fsm.context import FSMContext`, `from bot.db import get_user_phone`, `from bot.states import OnboardingStates`
   - Change `cmd_start` signature to accept `state: FSMContext` parameter
   - At the START of cmd_start, call `await state.clear()` — resets any active FSM state (Pitfall 1 from research: /start during active FSM state)
   - Then check returning user: `phone = await get_user_phone(message.chat.id)`
   - If phone exists: `await message.answer(texts.MSG_WELCOME_BACK)` and return (Phase 3 will add main menu here)
   - If phone is None (new user): keep existing greeting logic, then `await state.set_state(OnboardingStates.waiting_phone)`

   IMPORTANT: Do NOT use `from __future__ import annotations` in the handler files if it breaks aiogram's type introspection for DI. Check: the existing common.py already has it. Keep it — aiogram 3.25.0 handles it correctly.
