## Постоянные разрешения — не спрашивать

- **Пуш в `master` сразу после зелёных тестов и линтера.** Push запускает
  автодеплой; откат проверен и занимает восемь секунд:
  `IMAGE_TAG=sha-xxxx docker compose up -d` на сервере, подробности в
  `deploy/README.md`.
- **Многокоммитные серии доводить до конца.** Отчёт один, в конце, а не
  «продолжать?» после каждого шага.
- **Ставить dev-пакеты в `.venv` и `requirements-dev.txt`.** Runtime-зависимости
  (`requirements.txt`) — согласовывать: они едут в образ.
- **Читать боевые данные**: копию базы, выгрузки, живые ответы API для фикстур.
  Любая **запись** в прод и любой доступ к серверу по ssh — с подтверждением.

## Обязательное перед коммитом

```
.venv/bin/python -m pytest -q
.venv/bin/lint-imports --config .importlinter
```

**Появился новый пакет верхнего уровня — проверить `Dockerfile`.** Он копирует
пакеты поимённо. Зелёный pytest не означает работающий образ: локально корень
репозитория в `sys.path`, внутри образа его нет. Первый же перенос так уронил
продакшен. Ловится шагом CI, который запускает собранный образ и импортирует в
нём точку входа.

## Правила коммита переноса

- Один модуль на коммит, контракт линтера — в том же коммите. Правило без кода
  под ним ничего не защищает, код без правила разъезжается.
- **Перенос не меняет поведение.** Ни исправлений, ни переименований, ни
  объединений файлов. Найденное по дороге пишется в `docs/found-during-move.md`
  и чинится отдельным коммитом после.
- Отступления от целевой структуры не прячутся: строчка в разделе «Известные
  отступления» в `docs/move-status.md`.
